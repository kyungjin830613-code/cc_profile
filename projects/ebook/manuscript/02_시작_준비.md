# 2장. 시작 준비 — 첫날 반나절이면 끝나는 세팅

> v0.2 (2026-11-25, 사실 확인 반영).

## 이 장에서 얻는 것

- 앱인토스에 앱을 올리기 전에 **딱 한 번** 해 두면 되는 준비 5가지
- 우리가 준비를 건너뛰어서 **출시 당일에 막혔던 곳 3군데**와 피하는 법
- AI에게 일을 맡길 작업 환경 만들기(개발자 아니어도 됨)
- 끝에 붙은 **준비 체크리스트 12칸**만 채우면 3장으로 넘어가도 된다

---

## 2-1. 우리가 실제로 막혔던 곳부터

준비 단계는 지루하다. 그래서 다들 건너뛴다. 우리도 그랬다. 그 결과:

**막힘 ① 출시 버튼을 눌렀더니 "약관에 먼저 동의해 주세요"**
검수 승인 메일을 받고 신나서 '출시하기'를 눌렀다. 그런데 출시 대신 약관 창이 떴다. 워크스페이스 약관(제휴 서비스 이용약관, 보안관리 약관, 대표자 확인)은 **처음 출시할 때 한 번** 동의해야 한다. 동의 페이지가 처음엔 오류 화면으로 뜨기도 했다(새로고침으로 해결). 승인 메일을 받은 날 바로 못 내고 하루가 밀렸다.
→ **처방:** 가입한 날, 콘솔 작업공간 약관 페이지에서 미리 동의해 둔다(2-3).

**막힘 ② 사업자 정보가 필요한 순간이 생각보다 빨리 온다**
광고 수익 정산, 게임 앱, 정산 계좌 등록은 사업자 정보가 있어야 한다. 우리는 사업자는 있었지만 **업종에 소프트웨어 개발이 없었다.** 홈택스에서 업종을 추가(정정)하고 승인 문자를 받는 데 하루, 토스 콘솔에 사업자 정보를 올리고 검토받는 데 영업일 1~2일이 걸렸다.
→ **처방:** 앱을 만들기 전에 사업자 계획부터 정한다(2-4).

**막힘 ③ 사람만 할 수 있는 버튼이 있다**
AI가 코드를 쓰고, 콘솔 입력칸을 채우고, 번들을 올리는 것까지 다 했다. 그런데 **로그인, 본인인증, 약관 동의, 서약 체크, 휴대폰 테스트**는 사람이 해야 했다. 이걸 몰라서 밖에서 휴대폰으로 지시하다가 "PC 앞에 가야 하는 일"이 계속 쌓였다.
→ **처방:** 사람이 할 일을 미리 목록으로 정하고, 한자리에서 몰아서 한다(2-6).

## 2-2. 준비물 한눈에 보기

| 준비물 | 왜 필요한가 | 언제 | 걸린 시간(우리) |
|---|---|---|---|
| 토스 앱이 깔린 휴대폰 | 내 앱을 직접 테스트(QR·푸시) | 처음부터 | - |
| 토스 비즈니스 계정 | 앱인토스 콘솔 로그인 | 가입 첫날 | 10분 안팎(본인인증 포함) |
| 앱인토스 워크스페이스 | 내 앱들이 모이는 '회사' 단위 | 가입 첫날 | 5분 |
| 워크스페이스 약관 동의 | 출시하려면 필수 | **가입 첫날 미리** | 2분 |
| 사업자 등록(+업종) | 광고 정산, 게임, 정산 계좌 | 수익화·게임 전 | 1~3일 |
| PC + AI 코딩 도구 | AI가 코드를 쓰고 빌드하는 곳 | 첫 앱 전 | 30분~1시간 |

## 2-3. 토스 비즈니스 가입과 워크스페이스 만들기

1. PC 크롬에서 앱인토스 콘솔에 들어간다. 토스 비즈니스 계정으로 로그인한다. 계정이 없으면 이 화면에서 가입한다(휴대폰 본인인증).
2. 처음 들어가면 **워크스페이스**를 만든다. 워크스페이스는 내 앱들이 모이는 묶음이다. 워크스페이스 이름은 내부 관리용이다. 사용자에게 '만든 곳'으로 보이는 건 따로 정하는 **제작자 이름**(10자 이내, 한글·영문·숫자)이라, 이건 브랜드 이름으로 짓는다. 제작자 이름이 반영되는 데 10분쯤 걸린다.
3. **바로 약관 동의까지 한다.** 콘솔의 작업공간 약관 페이지에서 필수 약관 2개와 "이 서비스를 운영하는 대표자 또는 대리인입니다"에 체크하고 '동의하고 시작하기'를 누른다. [그림 2-1]
   - 페이지가 "에러가 발생했어요"로 뜨면 새로고침 한두 번이면 열린다(우리 경험).

> **워크스페이스 하나에 앱을 많이 올릴 때 주의**
> 토스는 같은 워크스페이스에서 **목적이 서로 다른 앱**만 받는다. 핵심 기능이 비슷한 앱을 같은 워크스페이스에서 여러 개 출시하는 것은 공식 정책으로 금지돼 있다. 실제로 AI 사주·AI 궁합·AI 점성술을 따로 냈다가 하나로 합치라는 요구를 받은 사례가 공개돼 있다. 그래서 우리는 운세 앱을 두 개(지갑궁합·신년운세)에서 멈췄다. 자세한 건 3장.

## 2-4. 사업자, 지금 필요할까?

결론부터: **처음 앱 하나를 올려 보는 데는 사업자가 없어도 된다.** 하지만 아래 중 하나라도 계획에 있으면 미리 준비한다.

| 이럴 때 | 사업자 필요 | 우리 판단 |
|---|---|---|
| 앱에 광고를 붙여 수익을 받고 싶다 | 광고 ID는 사업자 없이 받을 수 있다. 워크스페이스 누적 예상 수익이 5천 원에 닿으면 5영업일 안에 사업자·정산 정보를 등록해야 하고, 안 하면 미니앱이 일시적으로 노출되지 않는다 | 처음엔 광고 없이 출시, 반응 보고 붙인다 |
| 게임 앱을 내고 싶다 | 게임 등급분류와 함께 **게임제작업 등록**이 일반적으로 필요 | 키우기 게임 1개는 등록 절차를 밟는 중 |
| 정산 계좌를 등록하고 싶다 | 필요 | 사업자 검토 승인 뒤 등록 |

**이미 사업자가 있다면 업종을 확인한다.** 우리 사업자는 전자상거래 업종만 있었다. 앱으로 수익을 내려면 소프트웨어 업종이 맞다. 홈택스에서 '사업자등록 정정'으로 아래 업종을 추가했다.

- 응용 소프트웨어 개발 및 공급업
- 모바일 게임 소프트웨어 개발 및 공급업(게임 계획이 있으면)

신청 다음 날 승인 문자가 왔다(업종 코드는 홈택스 업종 검색 화면에서 확인한다). 그다음 토스 콘솔 '내 정보'에서 사업자 정보를 등록하면, 토스 검토에 영업일 1~2일이 걸린다.

> **주의:** 세금·업종 선택은 사업 형태에 따라 다르다. 이 책은 우리가 한 순서를 보여 줄 뿐이고, 내 상황에 맞는 업종·과세 유형은 홈택스 안내나 세무 상담으로 확인한다.

## 2-5. AI에게 일을 맡길 작업 환경

개발자가 아니어도 된다. 우리가 쓴 구성은 이렇다.

1. **PC 한 대(Windows든 Mac이든)**: 코드를 만들고 빌드하는 곳.
2. **AI 코딩 도구**: 우리는 Claude Code를 썼다. 토스 공식 문서에도 Claude Code·Cursor·Codex로 미니앱을 만드는 튜토리얼이 있다. 도구는 취향대로 고르면 된다.
3. **Node.js**: 앱을 빌드하는 프로그램. 설치는 AI에게 "Node.js LTS 설치하고 버전 확인해 줘"라고 시키면 된다.
4. **크롬**: 콘솔 작업용. AI가 화면을 대신 입력하게 하려면 브라우저 자동화 도구를 연결한다(선택).

**AI에게 처음 보낼 지시문(그대로 복사해서 써도 된다)**

```
앱인토스(토스 미니앱) 개발 환경을 준비해 줘.
1) Node.js LTS가 있는지 확인하고 없으면 설치
2) 작업 폴더 D:\miniapps 를 만들고, 앱인토스 공식 문서의 웹(WebView) 템플릿으로 샘플 앱 하나를 만들어
3) 화면은 토스 디자인 시스템(TDS: @toss/tds-mobile)으로 만들 것
4) npm run dev 로 브라우저에서 열리는지, 빌드 명령으로 .ait 파일이 만들어지는지 확인
5) 각 단계 결과를 한 줄씩 보고. 로그인이나 결제가 필요하면 멈추고 알려 줘.
```

> **3번이 중요한 이유:** 토스는 미니앱 화면에 **TDS(토스 디자인 시스템)** 사용을 권장한다. 필수는 아니지만, 토스 앱과 어울리는 화면은 사용자가 편하게 쓰고 완성도도 높아 보인다. 우리는 늦게 적용해서 이미 만든 앱 11개를 TDS로 다시 만들었다. 처음부터 TDS로 시작하면 이 일을 통째로 건너뛴다. 5장에서 자세히.

**밖에서 휴대폰으로 일 시키기(선택)**
우리는 PC를 켜 두고 밖에서 휴대폰으로 지시했다. 우리는 Claude Code의 **Remote Control(원격 연결)** 기능으로 PC의 AI를 휴대폰·클라우드 채팅에 연결했다. 휴대폰에서 보낸 지시를 PC의 AI가 받아 처리한다(설정 방법은 사용하는 도구의 공식 문서를 따른다). 출퇴근길에 "N빵 정산기 만들어 줘"라고 보내면, 집에 오기 전에 코드·테스트·로고까지 되어 있었다. 단, 아래 '사람만 하는 일'은 결국 PC 앞에서 해야 한다.

## 2-6. 사람만 할 수 있는 일 목록

AI가 아무리 잘해도 아래는 본인이 한다. 보안 때문에 일부러 사람에게 남겨 둔 단계다.

| 할 일 | 언제 | 소요 |
|---|---|---|
| 토스 비즈니스 로그인·본인인증 | 콘솔 처음, 세션이 끊길 때 | 1분 |
| 워크스페이스 약관 동의 | 가입 첫날(미리!) | 2분 |
| 사업자 정보 등록·정산 계좌 | 수익화 전 | 10분 |
| 휴대폰으로 내 앱 테스트(QR·푸시) | 앱마다 검토 요청 전 | 앱당 2~3분 |
| 서약 체크(검토 요청 전 확인 항목) | 앱마다 | 앱당 1분 |
| 공개 SNS 글 최종 게시 | 홍보할 때 | 1분 |

**팁:** 이 목록을 하루 한 번, 한자리에서 몰아서 한다. 우리는 "PC 앞에 앉았어"라고 AI에게 말하면, AI가 지금 사람이 눌러야 할 화면을 순서대로 띄우게 했다.

## 2장 정리

- 준비는 반나절이면 끝난다. 대신 **약관 동의와 사업자 계획은 첫날** 해 둔다.
- 워크스페이스 하나에는 **목적이 서로 다른 앱**만 올린다.
- 작업 환경은 PC + AI 코딩 도구 + Node.js + 크롬. 첫 지시문에 **TDS로 만들 것**을 꼭 넣는다.
- 로그인·인증·약관·서약·휴대폰 테스트는 사람이 한다. 몰아서 한다.

### 준비 체크리스트 (12칸)

- [ ] 휴대폰에 토스 앱 설치·로그인
- [ ] 토스 비즈니스 계정으로 앱인토스 콘솔 로그인
- [ ] 워크스페이스 만들기(브랜드 이름)
- [ ] 워크스페이스 약관 동의 완료
- [ ] 수익화 계획 정하기(광고 / 유료 기능 / 없음)
- [ ] 게임을 낼지 정하기(내면 등급분류·게임제작업 준비)
- [ ] 사업자 있으면 업종 확인(소프트웨어 업종)
- [ ] PC에 AI 코딩 도구 설치
- [ ] Node.js 설치 확인
- [ ] 샘플 앱이 브라우저에서 열리는지 확인
- [ ] 샘플 앱 .ait 빌드 성공
- [ ] '사람만 하는 일' 목록을 휴대폰 메모에 저장

다음 장에서는 **무엇을 만들지** 정한다. 여기서 반려의 절반이 결정된다.
