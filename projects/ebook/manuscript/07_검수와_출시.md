# 7장. 검수와 출시 — 테스트부터 '출시하기'까지 한 번에

> 초안 v0.1 (2026-11-25, 리야). [확인]은 출간 전 콘솔·공식 문서로 다시 확인할 곳, [캡처]는 화면을 넣을 곳, [채움]은 실제 기록을 넣을 곳.

## 이 장에서 얻는 것

- 번들 업로드부터 출시까지 **8단계 순서**와 단계별 소요 시간(우리 기록)
- 사람이 해야 하는 단계와 AI가 해 둘 수 있는 단계 구분
- 승인 메일을 받고도 **바로 출시 못 한 이유**
- 반려됐을 때 대응 순서
- 끝에 **제출 전 체크리스트**(부록 G와 같음)

---

## 7-1. 등록 다음 날 저녁, 승인 메일

11월 23일 오후에 첫 두 앱(찰떡 지갑궁합·찰떡 신년운세)을 등록하고 검토를 요청했다. 다음 날, 두 앱 모두 **승인**됐다는 메일이 왔다 [캡처: 메일, 개인정보 가림].

신나서 '출시하기'를 눌렀다. 그런데 출시 대신 **"출시하려면 약관에 먼저 동의해 주세요"** 창이 떴다(2장). 약관 동의 페이지는 처음엔 오류 화면으로 떴고, 새로고침해서야 열렸다. 마침 밖에 있어서 PC 앞에 갈 때까지 출시가 밀렸다.

PC 앞에 앉아 약관 세 칸에 체크하고 '동의하고 시작하기'를 누른 뒤, 그날 저녁 7시 18분에 지갑궁합, 7시 19분에 신년운세가 **"현재 출시됨"**이 됐다.

순서만 알았다면 승인 메일을 받은 그 순간 바로 출시할 수 있었다.

---

## 7-2. 8단계 순서

| 단계 | 할 일 | 누가 | 우리 소요 |
|---|---|---|---|
| ① 번들 업로드 | 빌드한 `.ait`를 콘솔에 올린다 | AI(브라우저 자동화) 또는 사람 | 앱당 2~3분 |
| ② 처리 대기 | 콘솔이 번들을 처리하면 '토스앱 테스트' 버튼이 켜진다 | - | 몇 분 |
| ③ 토스앱 테스트 | 휴대폰 토스 앱에서 QR을 찍거나 테스트 푸시를 받아 직접 실행 | **사람** | 앱당 2~3분 |
| ④ 서약 체크 | 검토 요청 전 확인 항목(우리 화면 기준 5개)에 체크 | **사람** | 앱당 1분 |
| ⑤ 검토 요청 | '검토 요청' 버튼 | 사람(또는 사람 지시를 받은 AI) | 1분 |
| ⑥ 검토 | 토스가 앱 정보·빌드를 검토 | 토스 | 우리 경우 하루 안팎 [확인: 공식 안내 기간] |
| ⑦ 약관 동의 | 워크스페이스 첫 출시 때 한 번 | **사람** | 2분 |
| ⑧ 출시하기 | '출시하기' → 확인 → "현재 출시됨" | 사람 또는 AI | 1분 |

> **③④⑦은 사람만 한다.** 앱이 여러 개면 이 세 단계를 하루 한 번 몰아서 한다(8장).

---

## 7-3. 단계별 요령

### ③ 토스앱 테스트
- QR: 콘솔 화면의 QR을 휴대폰 토스 앱으로 찍는다.
- 푸시: 콘솔에서 '테스트 푸시'를 보내면 휴대폰으로 알림이 온다. 앱이 여러 개일 때 편하다.
- 확인할 것: 첫 화면이 뜨는지, 핵심 버튼 한 번, 저장 후 닫았다 다시 열기, 공유 버튼.
- **번들을 새로 올렸으면 테스트도 새로.** 우리는 TDS로 바꾼 뒤 11개 앱 테스트를 다시 했다.

### ④ 서약 체크
- 검토 요청 전에 앱이 정책을 지키는지 스스로 확인하는 항목들이다 [확인: 항목 이름]. 내용을 읽고 체크한다. 체크했는데 사실과 다르면 반려 사유가 된다.

### ⑧ 출시하기
- 버전 이름(예: 20261123-1)과 출시 시각이 화면에 남는다. 책·홍보에 쓸 '증거'이니 캡처해 둔다.

---

## 7-4. 반려됐을 때

우리는 이 책을 쓰는 시점까지 **검수 반려는 아직 없었다**. 반려 대신 겪은 건 정책 사전 검사의 보류(3장)와 입력 오류(6장)였다. 사전에 걸러 낸 덕분이다. [채움: 출간 전까지 반려가 생기면 사례 추가]

반려가 오면 이 순서로 대응한다.

1. **사유 문장을 그대로 복사**해 둔다.
2. AI에게 사유와 해당 화면 캡처를 주고 **"이 사유에 해당하는 곳을 모두 찾아서 고칠 목록을 만들어"**라고 시킨다.
3. 목록을 사람이 확인하고 고친다(문구·화면·기능).
4. 새 번들 → 토스앱 테스트 → 서약 → 검토 요청을 다시 한다.
5. 사유와 고친 내용을 **반려 노트**에 남긴다. 다음 앱에서 같은 실수를 안 한다.

```
토스 미니앱 검수 반려 사유야: "(사유 그대로)"
- 이 사유에 해당할 수 있는 화면·문구·기능을 코드와 상세 정보에서 모두 찾아 목록으로
- 각 항목의 고칠 방법
- 고친 뒤 테스트·빌드 결과
- 반려 노트(사유 / 원인 / 고친 것) 한 줄 요약
```

**반려를 줄이는 습관(다른 개발자들의 공개 기록과 공식 가이드에서 자주 보이는 것)** [확인]
- 앱 아이콘·썸네일 규격과 실제 이미지가 맞는지
- 토스 내비게이션(뒤로가기·제목 줄)과 앱 안 내비게이션이 겹치지 않는지
- 광고를 붙였다면 광고 설정값이 맞는지
- 과장·허위 문구가 없는지

---

## 7장 정리

- 업로드 → 처리 → 토스앱 테스트 → 서약 → 검토 요청 → 검토 → (첫 출시만) 약관 → 출시하기.
- 테스트·서약·약관은 사람이 한다. 약관은 가입 첫날 미리.
- 번들을 바꾸면 테스트부터 다시.
- 반려는 사유를 그대로 AI에게 주고, 고친 내용은 반려 노트로 남긴다.

### 제출 전 체크리스트

- [ ] 최신 `.ait`를 올렸고 '토스앱 테스트' 버튼이 켜졌다
- [ ] 휴대폰 토스 앱에서 첫 화면·핵심 버튼·재실행·공유를 확인했다
- [ ] 상세 정보 입력값 점검표(6장)를 통과했다
- [ ] 로고·스크린샷 규격이 맞다
- [ ] 과장·허위 문구가 없다
- [ ] 서약 항목을 읽고 사실대로 체크했다
- [ ] 워크스페이스 약관 동의가 되어 있다(첫 출시)
- [ ] 검토 요청 후 승인 메일을 받으면 바로 '출시하기'

다음 장에서는 이 과정을 **앱 열네 개에 동시에** 돌린 방법, 그리고 밖에서 휴대폰으로 PC를 움직인 방법을 다룬다.
