# 4장. AI에게 일 맡기기 — 기획서 한 장에서 출시 파일까지

> v0.2 (2026-11-25, 사실 확인 반영).

## 이 장에서 얻는 것

- 개발을 몰라도 AI에게 앱을 맡기는 **5단계 순서**(기획서 → 계산 → 화면 → 확인 → 출시 파일)
- 그대로 복사해 쓰는 **지시문 6개**
- AI가 만든 앱에서 우리가 실제로 잡아낸 **버그 6건**과 잡는 법
- 예제: 「N빵 정산기」를 처음부터 끝까지 맡겨 보기
- 끝에 **AI 결과 검수 체크리스트**

---

## 4-1. "앱 만들어 줘" 한 줄로는 안 되는 이유

처음엔 이렇게 시켰다. "토스 미니앱으로 평수 계산기 만들어 줘."

AI는 금방 그럴듯한 앱을 만들었다. 화면도 예쁘고 버튼도 잘 눌렸다. 그런데 59㎡ 아파트를 넣었더니 **"23평형"**이 나왔다. 사람들이 흔히 '24평'이라고 부르는 집이다. 원인은 전용면적을 공급면적으로 바꾸는 비율(전용률)을 AI가 대충 정한 것이었다. 비율을 0.74로 고치고 나서야 59㎡ → 24평형, 84㎡ → 34평형이 맞게 나왔다.

AI는 **틀린 답도 자신 있게** 만든다. 그래서 우리는 일을 맡기는 순서를 바꿨다.

> **핵심 계산을 먼저 만들고, 정답표로 시험한 다음에, 화면을 입힌다.**

---

## 4-2. 다섯 단계 순서

| 단계 | AI가 하는 일 | 내가 하는 일 | 결과물 |
|---|---|---|---|
| ① 기획서 | 기능·화면·저장 방식을 한 장으로 정리 | 읽고 빼거나 더할 것 말하기 | `PRD.md` |
| ② 계산(핵심 로직) | 계산 부분만 따로 만들고 **테스트(정답표)**도 같이 작성 | 정답 예시 2~3개 주기 | 계산 파일 + 테스트 통과 |
| ③ 화면 | TDS 컴포넌트로 화면 만들기 | 휴대폰 크기 화면 보고 고칠 점 말하기 | 앱 화면 |
| ④ 확인 | 브라우저로 직접 눌러 보고 화면을 캡처해 보고 | 캡처를 보고 OK | 캡처 이미지 |
| ⑤ 출시 파일 | 빌드해서 `.ait` 파일 만들기, 로고 600×600 | 콘솔에 올릴지 결정 | `.ait`, 로고 |

이 순서의 장점은 **틀린 곳을 일찍 잡는다**는 것이다. 계산이 틀린 걸 화면 다 만든 뒤에 알면 고칠 곳이 많아진다.

---

## 4-3. 단계별 지시문

### ① 기획서

```
토스 미니앱 「N빵 정산기」 기획서를 PRD.md로 써 줘.
- 한 줄 소개, 다시 쓰는 이유, 기능 목록(우선순위), 화면 구성, 저장 방식
- 데이터는 서버로 보내지 않고 기기 안에만 저장
- 화면은 토스 디자인 시스템(TDS)으로
- 토스 정책상 문제가 될 수 있는 부분(금융 조언처럼 보이는 문구 등)이 있으면 따로 적어 줘
```

### ② 계산 + 정답표

```
N빵 정산기의 계산 부분만 따로 파일로 만들고, 테스트도 같이 써 줘.
정답 예시:
- 총 87,500원을 4명이 100원 단위로 나누면 1인당 21,900원, 총무가 100원 더 걷는다
- 고기집 90,000원(나 냄), 노래방 30,000원(친구1 냄), 3명이 전부 나누면
  친구2 → 나 40,000원, 친구1 → 나 10,000원
테스트를 돌려서 통과한 결과를 보여 줘. 통과 못 하면 계산을 고쳐.
```

> **정답 예시는 내가 준다.** 계산기를 만들 때 정답을 모르면 공식 자료에서 가져온다. 우리 「공과금 계산」은 한전·도시가스가 공개한 요금표와 계산 예시를 정답으로 넣어 맞을 때까지 고쳤다(요금표는 바뀌므로 앱에 '2026년 11월 기준'을 적었다).

### ③ 화면

```
계산 파일은 그대로 두고 화면만 만들어 줘.
- @toss/tds-mobile 컴포넌트 사용(Button, TextField, ListRow, SegmentedControl, BottomSheet 등)
- 토스 앱 안 저장소(Storage)를 쓰고, 토스 밖 미리보기에서는 브라우저 저장소로 대신
- 공유 버튼: 토스 안에서는 토스 공유, 밖에서는 문구 복사
- 휴대폰 화면 폭(390px) 기준
```

### ④ 확인

```
브라우저로 앱을 열어 직접 눌러 보고 결과를 보고해 줘.
1) 총 87,500원, 4명 입력 → 화면에 21,900원이 나오는지
2) 항목 두 개를 넣었을 때 송금 안내가 정답과 같은지
3) 오류(콘솔 에러)가 없는지
4) 휴대폰 크기 캡처를 보여 줘. 글자가 두 줄로 꺾이거나 버튼이 밖으로 삐져나온 곳이 있으면 고쳐.
```

### ⑤ 출시 파일

```
테스트 → 빌드 → .ait 파일 만들기까지 해 줘.
- apps-in-toss 설정의 appName은 '○○○'(6장에서 정한 이름)
- 로고: 600×600 PNG, 둥근 모서리 없이, 배경 꽉 차게, 밝은/어두운 모드 둘 다 잘 보이게, 아이콘 하나만
- 파일 위치와 크기를 보고해 줘
```

## 4-4. AI가 만든 앱에서 잡은 버그 6건

AI의 결과를 그대로 믿지 않고 **④ 확인 단계**에서 잡은 것들이다. 형식: 증상 → 원인 → 고친 값.

| # | 앱 | 증상 | 원인 | 고친 값 |
|---|---|---|---|---|
| 1 | 평수 계산기 | 59㎡가 23평형으로 나옴 | 전용률을 대충 정함 | 기본 전용률 0.74 → 24평형 |
| 2 | 오늘 점심 룰렛 | 당첨 메뉴와 바늘이 가리키는 칸이 다를 수 있음 | 회전 각도 계산 | 테스트로 "당첨 = 바늘 아래 칸" 확인 |
| 3 | 찰떡 떡집 키우기 | 다시 열 때마다 '새 떡 해금' 창이 또 뜸 | 마지막 해금 기록을 저장 안 함 | 처음 열 때는 창을 띄우지 않게 |
| 4 | 디데이 모아보기 | 하나 추가하면 '빠른 추가' 버튼이 사라짐 | 목록이 비었을 때만 보이게 만듦 | 항상 보이게 |
| 5 | 경조사비 장부 | 로고가 일장기처럼 보임 | 흰 바탕 위 빨간 원 하나 | 봉투 + 하트로 다시 그림 |
| 6 | 새해 소원 등불 | '오늘도 다짐'을 누르면 상세 창이 같이 열림 | 버튼과 줄 전체에 클릭이 겹침 | 상세 열기를 글자 부분으로 분리 |

**배운 것**
- 숫자가 나오는 앱은 **정답표 테스트**가 필수다(1, 2).
- 다시 열었을 때(재방문)의 동작은 AI가 자주 놓친다. **한 번 닫았다 다시 열어 보라**고 시킨다(3, 4).
- 로고·화면은 **캡처를 직접 본다.** AI는 "괜찮습니다"라고 보고해도 사람 눈에는 이상한 경우가 있다(5).

## 4-5. 예제 워크스루: 「N빵 정산기」 하루 만에

실제로 우리가 한 순서다. 걸린 시간은 대략이다.

1. **기획서(10분):** 간단 N빵(총액 ÷ 인원)과 항목별 정산(누가 냈고 누가 나눠 내나) 두 탭. 송금은 하지 않고 "누가 누구에게 얼마"만 계산. 정산 문구를 단톡방에 공유.
2. **계산 + 테스트(20분):** 끝자리 단위(1원·10원·100원·1,000원), 최소 송금 횟수로 정리. 테스트 8개 통과.
3. **화면(30분):** SegmentedControl로 탭, TextField로 금액, Button으로 '누가 냈어요' 고르기, ListRow로 송금 안내. [그림 4-1]
4. **확인(15분):** 87,500원 ÷ 4명 = 21,900원, 항목별 송금 안내 정답 일치. 입력칸이 카드 안에서 들여쓰기된 것, × 버튼이 밖으로 삐져나온 것을 캡처에서 발견해 고침.
5. **출시 파일(10분):** 빌드 → `.ait`, 로고(동전 나누기 그림) 600×600.

## 4-6. 토스 미니앱이라서 꼭 넣을 것

일반 웹사이트와 다른 점이다. 지시문에 넣어 두면 AI가 알아서 챙긴다.

| 항목 | 이유 |
|---|---|
| **TDS 사용** | 토스가 권장하는 디자인 시스템. 토스 앱과 어울리고 완성도가 올라간다(5장) |
| **토스 저장소 + 토스 밖 대체** | 토스 안에서는 토스 Storage, 미리보기(브라우저)에서는 브라우저 저장소. 그래야 밖에서도 테스트가 된다 |
| **토스 공유 + 복사 대체** | 토스 안에서는 공유 창, 밖에서는 문구 복사 |
| **앱 링크** | 공유 문구에 "나도 해 보기" 링크를 넣으면 새 사용자가 들어온다 |
| **기기 안 저장** | 서버가 없으면 개인정보 걱정과 서버 비용이 없다 |
| **appName 일치** | 설정 파일·코드·콘솔의 appName이 모두 같아야 한다(6장) |

## 4장 정리

- "만들어 줘" 한 줄 대신 **기획서 → 계산(정답표) → 화면 → 확인 → 출시 파일** 순서로 맡긴다.
- 정답 예시는 내가 준다. 모르면 공식 자료에서 가져온다.
- AI의 "다 됐습니다"를 믿지 말고 **캡처와 테스트 결과**를 본다.
- 다시 열었을 때의 동작, 글자 줄바꿈, 버튼 겹침은 AI가 자주 놓친다.

### AI 결과 검수 체크리스트

- [ ] 기획서를 읽고 기능을 확정했다
- [ ] 계산 부분에 정답표 테스트가 있고 모두 통과했다
- [ ] 화면이 TDS 컴포넌트로 만들어졌다
- [ ] 휴대폰 크기 캡처를 직접 봤다(줄바꿈·삐져나옴·겹침 없음)
- [ ] 앱을 닫았다 다시 열어도 기록이 남고, 이상한 창이 안 뜬다
- [ ] 콘솔 에러가 없다
- [ ] 공유 문구에 앱 링크가 들어 있다
- [ ] `.ait` 빌드가 성공했다
- [ ] 로고 600×600, 둥근 모서리 없음, 아이콘 하나
- [ ] appName이 설정·코드·콘솔에서 모두 같다

다음 장에서는 **TDS(토스 디자인 시스템)**를 다룬다. 우리가 앱 11개를 다시 만든 이유다.
