# 5장. TDS로 만들기 — 우리가 앱 11개를 다시 만든 이유

> v0.2 (2026-11-25, 사실 확인 반영).

## 이 장에서 얻는 것

- 토스가 권장하는 **TDS(토스 디자인 시스템)**가 무엇이고, 필수가 아닌데도 왜 쓰는 게 좋은지
- 처음부터 TDS로 시작하는 **설치 3줄과 기본 틀**
- 자주 쓰는 컴포넌트 **12개**와 화면별 조합법
- 우리가 11개 앱을 TDS로 바꾸며 만난 **함정 7가지**(증상 → 원인 → 고친 값)
- 공식 문서로 확인한 **로고 규칙**
- 끝에 **TDS·로고 점검표**

---

## 5-1. "그래픽이 좀 떨어지는 것 같아"

앱 열 개를 거의 다 만들었을 때, 화면을 본 사람이 말했다.

> "잘 만들긴 했는데… 그래픽이랑 이미지 퀄리티가 살짝 떨어지는 것 같아. 인기 앱이랑 비슷한 결로 만들어야 할 것 같아."

맞는 말이었다. 우리 앱들은 각자 색과 버튼 모양이 달랐다. 무지출 도장판은 초록, 공과금은 노랑, 소원 등불은 남색 밤하늘. 하나하나는 예뻤지만 **토스 안에 들어가면 남의 집 같았다.**

원인을 찾다가 앱인토스 문서와 예제에서 **TDS(토스 디자인 시스템)**를 봤다. 토스 앱이 쓰는 버튼·목록·입력칸 부품을 미니앱에서도 쓸 수 있게 공개한 것이다. 우리는 이걸 **검수에 꼭 필요한 기준**으로 읽었고, 그날 밤 열한 개를 전부 TDS로 다시 만들었다. 계산 로직과 테스트는 그대로 두고 화면만 갈아 끼웠기 때문에(4장의 순서 덕분이다) 하룻밤에 끝났다.

**그런데 책을 쓰며 공식 FAQ를 다시 확인해 보니, 우리가 잘못 읽었었다.**

> "모든 컴포넌트를 반드시 TDS로 디자인해야 하는 것은 아니에요." — 앱인토스 FAQ(디자인), 가능한 한 TDS 사용을 **권장**한다는 취지

비게임 출시 체크리스트에도 TDS 항목은 없다. 즉 TDS는 **필수가 아니라 권장**이다.

그래도 다시 만든 걸 후회하지 않는다. 바꾼 뒤 화면을 나란히 놓고 보니 차이가 분명했다. [그림 5-1: 바꾸기 전/후] 버튼 크기, 글자 간격, 목록 모양이 토스 앱과 같아지자 "토스 안의 기능"처럼 보였다. 처음 받은 지적("퀄리티가 떨어진다")이 사라졌다. 이 장은 그래서 **"반드시 써라"가 아니라 "쓰면 이렇게 좋아지고, 이렇게 쓰면 된다"**를 다룬다. 그리고 공식 문서는 한 번 더 확인하자는 교훈도.

---

## 5-2. TDS가 뭔가

TDS는 **토스 앱이 쓰는 버튼·목록·입력칸·시트 같은 부품 묶음**이다. 이걸로 만들면:

1. **토스 앱과 똑같은 느낌**이 난다. 사용자는 "토스 안의 기능"처럼 편하게 쓴다.
2. **글자 크기·간격·색이 이미 맞춰져 있다.** 디자이너가 없어도 된다.
3. **토스가 권장하는 방식이라** 화면 완성도에서 손해 볼 일이 없다.

게임은 예외다. 게임은 자기만의 그래픽을 쓴다.

## 5-3. 처음부터 TDS로 시작하기

### 설치 (AI에게 시키면 된다)

```
이 미니앱에 TDS를 설치해 줘.
- @toss/tds-mobile, @toss/tds-mobile-ait, @emotion/react 설치
- TDS가 요구하는 React 버전(18)에 맞춰 react, react-dom, @types/react를 맞출 것
- 앱 전체를 TDSMobileAITProvider로 감쌀 것
- 설치 후 테스트·빌드가 통과하는지 확인
```

**알아 둘 것**
- 우리가 쓴 버전은 `@toss/tds-mobile` 2.5.1, `@toss/tds-mobile-ait` 2.5.1이다(2026년 11월). 우리 환경에서는 이 버전이 React 18을 요구해서, React 19로 만들어진 템플릿을 18로 내렸다. 버전은 계속 바뀌니 설치할 때 AI에게 "호환 버전 확인"을 꼭 시킨다.
- 토스 밖(일반 브라우저)에서 미리보기를 열면 콘솔에 화면 안전 영역(SafeArea) 관련 오류가 뜬다. **토스 밖이라서 생기는 정상 현상**이다. 토스 앱 안에서는 나오지 않는다.

### 앱의 뼈대

```tsx
// main.tsx — 앱 전체를 TDS 공급자로 감싼다
<TDSMobileAITProvider>
  <App />
</TDSMobileAITProvider>
```

배경색·여백 같은 바탕은 공통 CSS 한 장으로 모든 앱에 같이 쓴다. 우리는 토스 색(배경 #f2f4f6, 카드 흰색, 글자 #191f28, 파랑 #3182f6)을 변수로 만들어 11개 앱이 같은 파일을 불러오게 했다.

## 5-4. 자주 쓰는 컴포넌트 12개

| 컴포넌트 | 어디에 | 우리 앱 예 |
|---|---|---|
| **Top** | 화면 맨 위 큰 제목+부제 | 돈 습관 결산 시작 화면 |
| **Paragraph.Text** | 본문 글자(크기 t1~t7) | 모든 앱 설명 글 |
| **Button** | 버튼. 크기 small~xlarge, 꽉 찬(fill)·연한(weak) | 룰렛 돌리기, 도장 찍기 |
| **BottomCTA** | 화면 아래 고정 큰 버튼 | 테스트 시작하기, 새 소원 적기 |
| **ListHeader** | 목록 위 소제목 | "최근 7일", "오늘의 다짐" |
| **ListRow** | 목록 한 줄(왼쪽 아이콘·가운데 글·오른쪽 값/버튼) | 경조사 기록, 송금 안내 |
| **SegmentedControl** | 2~4개 중 하나 고르는 탭 | 간단 N빵 / 항목별 정산 |
| **TextField** | 숫자·글자 입력칸(라벨·단위·도움말) | 총 금액 ○○원 |
| **TextArea** | 여러 줄 입력 | 소원 적기 |
| **Switch** | 켜고 끄기 | 오늘의 건강 체크 |
| **ProgressBar** | 진행률 막대 | 이번 달 목표, 퀴즈 진행 |
| **BottomSheet** | 아래에서 올라오는 창 | 메뉴 설정, 소원 상세 |
| (+) **Slider** | 값 끌어서 고르기 | 평수 계산기 전용률 |

**화면 조합 3가지(이것만 알아도 대부분 만든다)**

1. **계산기형**: SegmentedControl(탭) → TextField(입력) → 큰 숫자 결과 카드 → ListHeader + 표(계산 내역) → 공유 Button
2. **습관·기록형**: 머리글 → 오늘 상태 카드(ProgressBar) → 큰 Button(오늘 기록) → ListHeader + ListRow(지난 기록) → BottomSheet(설정)
3. **테스트·결과형**: Top + BottomCTA(시작) → ProgressBar + 선택 Button 질문 → 결과 카드 + ListRow(풀이) + 공유·저장 Button

## 5-5. TDS로 바꾸며 만난 함정 7가지

| # | 증상 | 원인 | 고친 값 |
|---|---|---|---|
| 1 | 설치하자마자 빌드 실패 | 템플릿이 React 19, TDS는 18까지 | react·react-dom·@types/react를 18로 |
| 2 | 선택 안 된 칩(버튼)이 거의 안 보임 | 연한 버튼에 `light` 색을 씀 | 선택 안 됨은 `variant="weak" color="dark"`, 선택됨은 `fill + primary` |
| 3 | 입력칸이 카드 안에서 한 번 더 들여쓰기됨 | TextField·SegmentedControl이 자체 좌우 여백을 가짐 | 카드 안에서는 바깥 여백을 그만큼 빼 줌 |
| 4 | 탭 글자가 두 줄로 꺾임("아파트 평형", "1,000원") | 탭 4개에 긴 글자 | 짧게: "아파트", "천원" |
| 5 | 결과 버튼 글자가 두 줄 | 반반 버튼에 긴 문구 | "이걸로 먹을래요" → "이걸로 먹기" |
| 6 | 목록의 '다짐' 버튼을 누르면 상세 창도 같이 열림 | 줄 전체 클릭과 버튼 클릭이 겹침 | 상세 열기는 글자 부분에만 |
| 7 | 밤하늘 같은 어두운 테마 앱이 혼자 튐 | 페이지 전체를 어둡게 칠함 | 페이지는 토스 밝은 바탕, 어두운 밤하늘은 **카드 한 장(포인트)**으로만 |

**배운 것:** TDS로 바꾸면 "예쁜 앱"이 아니라 **"토스 같은 앱"**이 된다. 개성은 화면 전체가 아니라 **포인트 하나**(룰렛 원판, 물컵, 등불 하늘)로 준다.

## 5-6. 로고 — 공식 규칙

앱인토스 개발자 문서(콘솔 가이드 '앱 로고')의 규칙이다(2026년 11월 확인).

| 규칙 | 공식 문구(요약) |
|---|---|
| 크기 | "정사각형 600 × 600px, PNG 파일" |
| 모서리 | "모서리가 둥근 형태는 사용할 수 없어요" |
| 배경 | "배경색 필수, 투명 배경은 쓸 수 없어요" |
| 금지 ① | "토스에서 제공하는 아이콘과 이미지 리소스 등은 앱 로고로 쓸 수 없어요(2차 가공 포함)" |
| 금지 ② | 사람 얼굴이 들어간 이미지는 AI로 만든 것이라도 쓸 수 없다 |
| 선택 | 다크 모드용 로고를 따로 올릴 수 있다 |

**우리 로고 원칙(공식 규칙은 아니고 우리 선택):** 연한 단색 배경 + 깔끔한 물건 하나. 작은 크기에서도 한눈에 알아보게. 예) 하루 영단어 = 연파랑 배경에 "Aa" 단어 카드 한 장.

**실패 사례:** 경조사비 장부 첫 로고는 흰 바탕에 빨간 동그라미라 **일장기처럼 보였다.** 봉투+하트로 다시 그렸다. 로고는 반드시 작게 줄여서(앱 목록 크기) 사람 눈으로 확인한다.

**AI 지시문**

```
이 앱 로고를 만들어 줘.
- 600×600 PNG, 정사각형, 둥근 모서리 없음, 배경 꽉 채움(투명 금지)
- 연한 단색 배경 + 앱을 상징하는 물건 하나만(작게 줄여도 알아보게)
- 토스 아이콘·이미지 사용 금지, 사람 얼굴 금지
- 64×64로 줄였을 때도 알아볼 수 있게
- 만든 뒤 원래 크기와 64×64 크기 캡처를 둘 다 보여 줘
```

## 5-7. 이미 만든 앱을 TDS로 바꾸는 순서

이미 만든 앱이 있다면 이 순서로 한 개씩 바꾼다(우리는 앱당 20~40분).

1. 계산·저장 코드는 **건드리지 않는다**(테스트가 그대로 통과해야 한다).
2. TDS 설치 + 공급자 감싸기(5-3).
3. 화면 부분만 TDS 컴포넌트로 바꾼다(5-4의 조합 참고).
4. 테스트·빌드 통과 확인.
5. 휴대폰 크기 캡처로 함정 7가지(5-5) 점검.
6. 콘솔에 **새 번들로 다시 올린다.** 번들이 바뀌었으니 휴대폰 테스트도 다시 한다(7장).

```
이 앱의 화면을 TDS로 바꿔 줘.
- 계산·저장 코드와 테스트는 그대로 둘 것(테스트가 그대로 통과해야 함)
- 공통 바탕 CSS를 불러오고, 화면은 TDS 컴포넌트로
- 바꾼 뒤 휴대폰 크기 캡처를 보여 주고, 글자 줄바꿈·들여쓰기·겹침이 있으면 고쳐
- 테스트·빌드 결과를 보고해
```

## 5장 정리

- TDS는 **필수가 아니라 권장**이다. 그래도 처음부터 쓰면 토스 앱 같은 완성도를 공짜로 얻는다.
- TDS는 React 18. 공급자로 앱을 감싸고, 바탕 CSS는 공통 한 장.
- 컴포넌트 12개와 화면 조합 3가지면 대부분의 앱이 된다.
- 개성은 화면 전체가 아니라 포인트 하나로.
- 로고는 600×600 PNG, 둥근 모서리·투명 배경 금지, 토스 아이콘·사람 얼굴 금지.

### TDS·로고 점검표

- [ ] TDS(@toss/tds-mobile, -ait) 설치, React 18
- [ ] 앱 전체가 TDSMobileAITProvider로 감싸져 있다
- [ ] 버튼·목록·입력·탭·시트가 모두 TDS 컴포넌트다
- [ ] 선택 안 된 버튼도 잘 보인다(weak + dark)
- [ ] 글자가 두 줄로 꺾이는 버튼·탭이 없다
- [ ] 카드 안 입력칸이 이중으로 들여쓰기되지 않았다
- [ ] 페이지 바탕은 토스 밝은 색, 개성은 포인트 하나
- [ ] 로고 600×600, 둥근 모서리 없음, 배경 꽉 참
- [ ] 로고에 토스 아이콘·이미지, 사람 얼굴이 없다
- [ ] 로고를 64×64로 줄여 봐도 알아볼 수 있다
- [ ] 바꾼 뒤 새 번들로 다시 올리고 휴대폰 테스트를 다시 했다

다음 장에서는 콘솔 등록에서 막히는 것들, **이름 중복 9번과 입력칸 오류**를 전부 모았다.
