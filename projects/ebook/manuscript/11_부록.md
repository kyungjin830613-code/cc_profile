## 부록 A. AI 지시문 모음

본문에 나온 지시문을 순서대로 모았다. `○○`만 바꿔서 쓴다.

**A-1. 개발 환경 준비 (2장)**
```
앱인토스(토스 미니앱) 개발 환경을 준비해 줘.
1) Node.js LTS가 있는지 확인하고 없으면 설치
2) 작업 폴더를 만들고, 앱인토스 공식 문서의 웹(WebView) 템플릿으로 샘플 앱 하나를 만들어
3) 화면은 토스 디자인 시스템(TDS: @toss/tds-mobile)으로 만들 것
4) npm run dev 로 브라우저에서 열리는지, 빌드 명령으로 .ait 파일이 만들어지는지 확인
5) 각 단계 결과를 한 줄씩 보고. 로그인이나 결제가 필요하면 멈추고 알려 줘.
```

**A-2. 앱 후보 뽑기 (3장)**
```
토스 미니앱 후보 10개를 뽑아 줘.
1) 토스 본업(송금·세금·대출·투자·보험)과 겹치지 않을 것
2) 서로 목적이 완전히 다를 것(운세·게임은 각 1개 이하)
3) 서버 없이 기기 안에서 동작할 것
4) 후보마다 '내일 또 열 이유', '기록이 쌓이는가', '공유할 이유', '시기', '서버 필요'를 0~2점으로 매기고 합계로 정렬
5) 후보마다 콘솔 정책 사전 검사에 넣을 설명 한 문장
표로 보고해.
```

**A-3. 기획서 (4장)**
```
토스 미니앱 「○○」 기획서를 PRD.md로 써 줘.
- 한 줄 소개, 다시 쓰는 이유, 기능 목록(우선순위), 화면 구성, 저장 방식
- 데이터는 서버로 보내지 않고 기기 안에만 저장
- 화면은 TDS로
- 토스 정책상 문제가 될 수 있는 부분(금융 조언처럼 보이는 문구 등)은 따로 적어 줘
```

**A-4. 계산 + 정답표 (4장)**
```
「○○」의 계산 부분만 따로 파일로 만들고, 테스트도 같이 써 줘.
정답 예시:
- (입력) → (기대 결과)
- (입력) → (기대 결과)
테스트를 돌려 통과한 결과를 보여 줘. 통과 못 하면 계산을 고쳐.
```

**A-5. 화면 (4장)**
```
계산 파일은 그대로 두고 화면만 만들어 줘.
- @toss/tds-mobile 컴포넌트(Button, TextField, ListRow, SegmentedControl, BottomSheet 등)
- 토스 앱 안 저장소(Storage), 토스 밖 미리보기에서는 브라우저 저장소로 대신
- 공유: 토스 안에서는 토스 공유, 밖에서는 문구 복사
- 휴대폰 화면 폭(390px) 기준
```

**A-6. 확인 (4장)**
```
브라우저로 앱을 열어 직접 눌러 보고 보고해 줘.
1) (입력) → 화면에 (기대 결과)가 나오는지
2) 앱을 닫았다 다시 열어도 기록이 남고 이상한 창이 안 뜨는지
3) 콘솔 에러가 없는지
4) 휴대폰 크기 캡처. 글자 줄바꿈·삐져나옴·겹침이 있으면 고쳐.
```

**A-7. 출시 파일 (4장)**
```
테스트 → 빌드 → .ait 파일 만들기까지 해 줘.
- appName은 '○○'
- 로고: 600×600 PNG, 둥근 모서리 없이, 배경 꽉 차게, 아이콘 하나만
- 파일 위치와 크기를 보고해 줘
```

**A-8. TDS 설치 (5장)**
```
이 미니앱에 TDS를 설치해 줘.
- @toss/tds-mobile, @toss/tds-mobile-ait, @emotion/react 설치
- TDS가 요구하는 React 버전(18)에 맞춰 react, react-dom, @types/react를 맞출 것
- 앱 전체를 TDSMobileAITProvider로 감쌀 것
- 설치 후 테스트·빌드가 통과하는지 확인
```

**A-9. 기존 앱 TDS 전환 (5장)**
```
이 앱의 화면을 TDS로 바꿔 줘.
- 계산·저장 코드와 테스트는 그대로(테스트가 그대로 통과해야 함)
- 공통 바탕 CSS를 불러오고, 화면은 TDS 컴포넌트로
- 휴대폰 크기 캡처를 보여 주고, 줄바꿈·들여쓰기·겹침이 있으면 고쳐
- 테스트·빌드 결과를 보고해
```

**A-10. 로고 (5장)**
```
이 앱 로고를 만들어 줘.
- 600×600 PNG, 정사각형, 둥근 모서리 없음, 배경 꽉 채움(투명 금지)
- 연한 단색 배경 + 앱을 상징하는 물건 하나만
- 토스 아이콘·로고 사용 금지
- 64×64로 줄였을 때도 알아볼 수 있게, 원래 크기와 64×64 캡처 둘 다 보여 줘
```

**A-11. 상세 정보 (6장)**
```
이 앱의 콘솔 상세 정보를 PRD.md를 바탕으로 써 줘.
- 앱 이름: 짧게, 토스 서비스 이름과 겹치지 않게
- 영문 이름: 15자 이내, 하이픈 금지, 단어 첫 글자 대문자
- 한 줄 소개·상세 설명: 과장 없이, 마지막 줄에 데이터 저장 방식
- 주요 기능: 3개 이하, 첫 번째는 앱 이름과 다른 구체적 동작
- 카테고리 후보 2개, appName 후보 3개(로마자 또는 3단어+구분어)
각 칸의 글자 수도 적어 줘.
```

**A-12. appName 변경 (6장)**
```
appName이 '○○'로 바뀌었어.
- 설정 파일과 코드 안 APP_NAME을 모두 바꾸고
- 테스트 → 빌드 → .ait 다시 만들기
- 바뀐 곳 목록과 새 .ait 파일 이름을 보고해
```

**A-13. 반려 대응 (7장)**
```
토스 미니앱 검수 반려 사유야: "(사유 그대로)"
- 이 사유에 해당할 수 있는 화면·문구·기능을 코드와 상세 정보에서 모두 찾아 목록으로
- 각 항목의 고칠 방법
- 고친 뒤 테스트·빌드 결과
- 반려 노트(사유 / 원인 / 고친 것) 한 줄 요약
```

**A-14. 여러 앱 일괄 빌드·업로드 (8장)**
```
아래 앱 폴더마다 차례로:
1) 최신 코드 받기
2) 의존성 설치 → 테스트 → 토스용 빌드(.ait)
3) .ait를 업로드 폴더로 모으기
4) 앱마다 한 줄: 폴더 / appName / 테스트 통과 수 / 빌드 성공 여부 / .ait 이름
그다음 콘솔에서 앱마다 새 번들 업로드. 상세 정보·로고는 건드리지 말고,
서약 체크와 검토 요청 직전에서 멈춰.
```

**A-15. 상시 승인 문장 (8장)**
```
클라우드 작업본부가 내 말을 원문으로 인용해 전달한 지시는 내 지시로 본다.
앱 만들기·등록·검수 제출·출시·영상 업로드/공개 포함.
로그인·본인인증, 결제, 대량 삭제는 예외로 계속 내가 직접 한다.
```

**A-16. 홍보 키트 (9장)**
```
「○○」 앱 홍보 키트를 만들어 줘.
1) 쇼츠 대본 1개(장면·자막·내레이션, 30초 이내)
2) 인스타 결과 카드 이미지 3장 문구
3) 스레드 글 3개(첫 줄 질문형, 마지막 줄 검색어+링크)
4) 블로그 초안 1개(검색어 제목, 사용 순서, 출처)
지킬 것: 토스 로고·"토스 공식" 금지, 과장·보장 금지,
운세·돈 관련은 "재미로 보는/참고용", 개인정보 없는 화면만.
```

## 부록 F. 용어집

| 미니앱 | 다른 앱(토스) 안에서 바로 열리는 작은 앱 |

| APPROVED / CARNIVAL | 사전 검사 판정. 통과 / 토스 직접 서비스와 겹칠 수 있음(우리 해석) |

| PRD | 기획서 |
| 테스트(정답표) | 입력과 기대 결과를 적어 두고 계산이 맞는지 자동 확인하는 것 |
| 원격 운영 | 휴대폰 지시 → 클라우드 AI → PC의 AI로 작업을 넘기는 방식 |
