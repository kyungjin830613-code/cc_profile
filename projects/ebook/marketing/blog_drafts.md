# 블로그 검색용 글 5편 (네이버 블로그·티스토리)

공통: 제목에 검색어 그대로. 본문 1,500~2,500자, 캡처 2~4장(개인정보 가림), 공식 문서 링크, 끝에 "자세한 순서와 체크리스트는 전자책에 정리했어요 → (리틀리 링크)". 책 본문을 통째로 옮기지 않는다(요약 + 예시 1개).

---

## 1. 앱인토스 정책 사전 검사 하는 법, CARNIVAL 뜻
- 도입: 테스트 16개 통과한 연말정산 앱을 접은 이야기
- 본문
  1. 앱 만들기 창에 설명만 넣으면 판정이 먼저 보인다
  2. 문구가 없으면 통과(우리 13건), 경고 문구가 뜨면 위험(우리 1건) — 실제 문구 인용
  3. '만들기'를 누르지 않는 이유(appName이 묶임)
  4. 토스 본업과 겹치는 주제는 위험(세금·대출·투자·보험)
- 마무리: 판정 14건 표 일부 + 책 링크

## 2. 앱인토스 appName 중복 해결 ("이미 사용 중인 appName이에요")
- 도입: 하루 9번 막힌 기록
- 본문
  1. 이름 3종(앱 이름 10자 / 영문 이름 / appName) 정리
  2. 중복 7건 표(gyeongjo-book → gyeongjo-memo 등)
  3. 통과율 높은 3원칙(로마자, 3단어+구분어, 후보 3개)
  4. 이름 바뀌면 코드도 바꾸고 다시 빌드
  5. 영문 이름 오류 문구 원문 3개
- 마무리: 입력값 체크리스트 일부 + 책 링크

## 3. 토스 미니앱 TDS 꼭 써야 하나요? (필수 vs 권장)
- 도입: "검수 기준"인 줄 알고 11개를 다시 만든 이야기
- 본문
  1. 공식 FAQ: 반드시 TDS여야 하는 건 아니다, 권장
  2. 그래도 쓰면 좋은 이유(토스 앱과 같은 느낌, 디자이너 없이 완성도)
  3. 전/후 캡처
  4. 자주 쓰는 컴포넌트 5개와 함정 3개(React 버전, 연한 버튼, 들여쓰기)
- 마무리: 책 5장 안내

## 4. 토스 미니앱 검수 기간과 출시 순서 (약관 동의 주의)
- 도입: 승인 메일 받고도 출시를 못 한 이유(약관)
- 본문
  1. 업로드 → 테스트 → 서약 → 검토 요청 → 검토 → 약관 → 출시하기
  2. 검토 기간: 우리는 하루 안팎, 공식 안내는 문서마다 다름 → 일주일 잡기
  3. 서약 5개(카테고리에 따라 7개) 원문
  4. 출시 후 약 1시간 뒤 반영, 핵심 지표 먼저 등록
- 마무리: 제출 전 체크리스트 일부 + 책 링크

## 5. 토스 미니앱 '홍보 소재 맡기기' 써 본 후기 (스레드 조회 2,418)
- 도입: 출시 축하 화면의 버튼
- 본문
  1. 무엇을 주나(글 1개 + 이미지 10장, 하루 10번 다시 만들기)
  2. 그대로 올리면 안 되는 이유와 고친 표
  3. 글 구조 6단계
  4. 결과 숫자(게시 15시간 뒤 조회 2,418 · 반응 57 · 팔로워 +6)
  5. 출시 후 7일 루틴
- 마무리: 책 9장 안내
