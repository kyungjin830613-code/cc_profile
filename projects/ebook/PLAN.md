# 전자책 프로젝트 기획서

작성: 리야, 2026-11-24. 사용자 지시 원문: "그러면은 전자책 프로젝트도 너가 음, 지금부터 그 기획하고 그리고 기획서 만들어서 지침 파일에 저장해."

## 1. 목표

- 우리가 **직접 해 본 일**을 전자책으로 묶어 판다. 남의 글을 요약한 책이 아니라 실제 기록과 화면으로 만든 책.
- 1권을 3개월 안에 내고, 반응을 보며 시리즈로 늘린다.
- 판매 수익 + 유튜브·스레드·토스 미니앱과 서로 홍보하는 구조를 만든다.

## 2. 책 후보 (우리 경험에서 나온 주제)

| 순위 | 가제 | 근거가 되는 우리 작업 | 사려는 사람 |
|---|---|---|---|
| **1** | **AI와 둘이서 토스 미니앱 10개 출시하기** | 앱인토스 가입~출시 전 과정, 정책 사전 검사, TDS 검수 기준, 로고 규칙, 반려 피하는 법, 홍보 | 부업·1인 개발 입문자, 비개발자 |
| 2 | AI로 유튜브 쇼츠 채널 만들기 (일상비화 제작기) | 기획→장면 생성→편집→업로드→성과 분석 | 쇼츠 부업 입문자 |
| 3 | 1인 사업자, 홈택스로 업종 추가하고 플랫폼에 등록하기 | 사업자 업종 정정, 토스 사업자 등록, 게임제작업 준비 | 앱·콘텐츠로 사업자 내려는 사람 |

**1권은 1번 추천.** 이유: 아는 사람이 아직 적은 주제이고(미니앱 1만 5천 개 중 실제로 쓰이는 건 1%도 안 된다는 토스 발표), 우리가 가입부터 출시·홍보까지 실제로 해 봤다.

## 3. 1권 목차 초안 — 「AI와 둘이서 토스 미니앱 10개 출시하기」

**제목 원칙(시장 조사 반영):** 팔리는 책은 제목에 구체적 숫자+기간이 있다. 우리는 **콘솔에 남은 사실 숫자만** 쓴다. 후보: 「비개발자가 이틀 만에 토스 미니앱 14개 등록, 2개 출시한 실제 기록」(출간 시점 숫자로 갱신). 수익 숫자는 실제로 생긴 뒤에만.

**장 구성 틀(모든 장 공통):** ① 이 장에서 얻는 것 ② 우리가 실제로 막힌 곳(실패담) ③ 단계별 방법(표·화면·AI 지시문) ④ 정리 ⑤ 체크리스트. 근거: `RESEARCH.md` 6절.

**확정 목차 v1 (11-24, `research/toc_analysis.md` 반영)** — 잘 팔리는 흐름(숫자 공개 → 왜 지금 → 준비 → 단계별 실행 → 막힌 곳 → 수익·운영 → 회고 → 부록)에, 경쟁 앱인토스 전자책 14권 이상이 다루지 않는 빈 곳 5개(★)를 한 장씩 넣었다.

- 프롤로그 ✅ v0.1. 숫자로 시작: 이틀, 등록 앱 수, 출시 앱 수, 반려·보류 건수(정직한 작은 숫자 포함)
1. 왜 하필 토스 미니앱인가 ✅ v0.1
2. 시작 준비 — 첫날 반나절 세팅 ✅ v0.1
3. ★ 무엇을 만들까 — 정책 사전 검사 실측표(APPROVED·CARNIVAL 9건), 비슷한 앱 규칙 ✅ v0.1
4. AI에게 일 맡기기 — 기획서→코드→테스트→브라우저 확인, 지시문 쓰는 법, 예제 앱 1개 워크스루 ✅ v0.1
5. ★ TDS로 만들기 — 검수 기준, 11개 앱을 TDS로 다시 만든 기록, 자주 쓰는 컴포넌트, 로고 600×600 규칙 ✅ v0.1
6. ★ 콘솔 등록에서 막히는 것 전부 — appName 중복 9건, 토스 서비스명 금지, 영문 이름·기능 이름 입력 규칙 오류 모음('증상 → 원인 → 고친 값') ✅ v0.1
7. 검수와 출시 — 휴대폰 테스트(QR·푸시) → 서약 → 검토 요청 → 승인 → 약관 → 출시하기 순서, 반려 대응 ✅ v0.1
8. ★ 여러 앱을 한 번에 굴리기 — 워크스페이스 하나로 14개 운영, 번들 일괄 재업로드, 휴대폰으로 지시하고 PC의 AI가 콘솔을 조작하는 원격 운영 ✅ v0.1
9. ★ 출시 후 홍보 — '토스에게 홍보 소재 맡기기'(AI 글·이미지 → 스레드), 채널별 홍보 키트, 출시 후 7일 루틴 ✅ v0.1
10. 숫자로 보는 결과와 회고 — 앱별 방문·재방문, 점수표 예측 vs 실제, 다음에 다르게 할 것 ✅ v0.1
- 부록 ✅ v0.1: A 지시문(프롬프트) 모음 / B 콘솔 입력값 체크리스트(글자 수·금지 문자) / C 정책 사전 검사 판정표 / D 카테고리 경로표 / E 출시 후 7일 홍보 루틴 / F 용어집 / G 제출 전 체크리스트

분량 목표: **본문 100~150쪽 + 부록**(11-24 확정). 경쟁 앱인토스 전자책은 41~148쪽(중간 약 60쪽)이라 '가장 두꺼운 실전서' 자리를 잡는다. 400쪽처럼 늘리지 않고 표·캡처·체크리스트 밀도로 승부한다. 글 70% 이상(크몽 이미지 30% 규칙).

**차별점(시장 조사 결과, `RESEARCH.md`):** 토스 공식 튜토리얼·웨비나는 무료라 '개발 따라 하기'만으로는 안 팔린다. 우리 책은 ① 실제로 10개 넘게 만들어 출시한 기록 ② 반려·정책 사례(CARNIVAL, 이름 중복, TDS 필수) ③ 출시 후 사람 모으기(홍보)에 집중한다. 앱인토스·토스 미니앱 전자책은 이미 **14권 이상**(14,000~49,000원, 41~148쪽) 있지만 모두 리뷰 0~3개라 1등이 없는 초기 시장(`research/kmong_top10.md`, `research/toc_analysis.md`). 8권 모두 TDS·홍보를 다루지 않는다. 그중 "반려 기록"을 내세운 책(58p)도 있어, 범위와 실무 자료(판정표·오류 모음·지시문)로 앞선다.

## 4. 어디서 팔까 (조사 결과, 2026-11-24)

| 곳 | 역할 | 수수료(확인 정도) |
|---|---|---|
| **크몽** | 전자책 장터. 구매자·리뷰가 많아 첫 판매에 유리 | 판매자 서비스 이용료 구간제 70만 원 이하 16.4% / 70만~200만 9.4% / 200만 초과 4.4%, 결제망 이용료 3.3%, 부가세 별도(2024-07 시행으로 여러 자료가 일치. **크몽 공식 안내로 최종 확인 필요**) |
| **리틀리** | 내 판매 페이지(링크 한 개). 유튜브·스레드에서 사람을 보내는 곳 | 판매 수수료 1~5%(누적 결제액이 늘수록 낮아짐), PG 수수료·부가세 별도, 정산 매주 금요일(리틀리 공식 페이지 기준, 구간표가 페이지마다 달라 **판매 전 요금제 페이지 재확인**) |
| 와디즈 | 펀딩으로 먼저 팔아 보기(사전 판매) | 미확인 |
| 교보 퍼플·부크크 등 | 일반 서점 유통 | 자료마다 수치가 크게 달라 **미확인** |

**판매 전략(제안):**
1. 크몽에 먼저 올려 리뷰를 모은다(신뢰).
2. 리틀리 페이지를 만들어 우리 채널(유튜브·스레드·토스 미니앱)에서 보내는 사람은 리틀리로 받는다(수수료 낮음).
3. 반응이 좋으면 와디즈·서점 유통을 검토한다.
4. 가격은 조사 단계에서 크몽 같은 주제 전자책 가격·리뷰 수를 보고 정한다.

## 5. 출간·홍보 계획 (1권)

### 언제 낼까
- **우리 앱의 출시 후 2~4주 지표(방문·재방문)가 나온 뒤** 낸다. 목표: 2026년 12월 말 원고 완성 → 2027년 1월 출간.
- 1월은 "새해 부업·새해 계획" 수요가 큰 시기라 홍보 문구와 맞다.

### 어디에 낼까 (순서)
1. **크몽**(메인 장터): 리뷰·신뢰를 쌓는 곳. 전자책 카테고리 IT·프로그래밍 또는 부업·창업.
2. **리틀리**(직접 판매): 우리 채널에서 오는 사람을 받는 곳. 수수료가 낮다. 무료 맛보기(1~2장 PDF)로 이메일·연락처 대신 **관심 표시만** 받는다.
3. 반응이 좋으면 **와디즈**(개정판·강의 묶음 펀딩), 그다음 서점 유통 검토.

### 가격
- 출시가 **29,000원**, 첫 2주 얼리버드 19,900원(가격대 조사 9,900~29,000원 구간 상단, 하루 강의 189,000원 대비 훨씬 쌈).
- 묶음 상품(2차): 전자책 + 지시문·체크리스트 템플릿 파일 → 39,000원.
- 최종 가격은 출간 직전 크몽 같은 분야 상위 10권 가격을 다시 보고 정한다.

### 어떻게 홍보할까
| 채널 | 무엇을 | 언제 |
|---|---|---|
| 유튜브 쇼츠 | "AI랑 토스 앱 10개 만들어 본 결과" 시리즈 5편(반려당한 이야기, 하루 만에 앱 만들기, 첫 사용자 숫자 공개 등). 끝에 "자세한 건 전자책" | 출간 3주 전부터 주 2~3편 |
| 스레드 | 제작 일기(매일 한 줄 + 화면 1장). 질문형 글로 댓글 모으기 | 지금부터 꾸준히 |
| 블로그 | 검색용 글: "앱인토스 반려 사유", "토스 미니앱 TDS", "토스 미니앱 수익" | 출간 1달 전부터 주 1편 |
| 토스 미니앱 | 앱 안 '만든 사람 이야기' 같은 링크는 토스 정책 확인 후에만 | 정책 확인 뒤 |
| 크몽 | 출간 첫 주 지인·구독자 리뷰(솔직한 후기만, 리뷰 조작 금지), 상세페이지에 목차·미리보기 | 출간 직후 |
| 무료 맛보기 | 1장(정책 사전 검사·반려 피하기)을 무료 PDF로 → 리틀리에서 배포 | 출간 2주 전 |

- 홍보 키트 만드는 방식은 `projects/TOSS_PROMO_GUIDE.md`와 같다(쇼츠 대본, 카드 이미지, 스레드 글, 블로그 초안).
- 게시 전 사용자 확인 → 게시 후 48시간 반응 보고.

### 숫자 목표(첫 3개월, 가늠치)
- 무료 맛보기 다운로드 300건 → 유료 전환 5~10% → 15~30권.
- 크몽 리뷰 10개.
- 이 숫자는 추정이고, 실제 결과로 다음 권 여부를 정한다.

## 7. 지킬 것

- 사실·수치는 출처 2곳 이상. 토스 정책처럼 바뀌는 내용은 "○년 ○월 기준"을 붙인다.
- 개인정보(사업자번호, 이메일, 실명 화면 등)는 캡처에서 가린다.
- 토스 로고·"토스 공식" 표현을 쓰지 않는다. 토스 화면 캡처는 설명에 필요한 만큼만.
- 수익을 약속하는 과장 금지("월 300 보장" 같은 말 쓰지 않기).
- Pixeling·지숙이 자동화 관련 내용은 책에 넣지 않는다.
- 결제·로그인·본인인증·정산 계좌 등록은 사용자가 직접.
